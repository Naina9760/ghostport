# Security policy

## Supported versions

Until the first tagged release, only the current `master` branch receives
security fixes. After releases begin, this file will list supported versions.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Contact the repository
owner, `Naina9760`, privately through an established channel and include:

- the affected commit or version;
- the required privileges and environment;
- reproduction steps or a minimal proof of concept;
- the potential impact;
- any suggested mitigation.

Do not include real packet captures, credentials, personal IP data, or destructive
payloads. The owner should enable GitHub private vulnerability reporting before
the first public release. This policy will then link directly to that reporting
form.

## Scope

Reports about unsafe BPF behavior, privilege boundaries, telemetry disclosure,
release integrity, dependency compromise, or remote event delivery are in scope.
General feature requests belong in the public issue tracker.
